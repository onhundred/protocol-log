# Loops: how to write them and which to pick

How an agent (or a person) proposes, names and picks loops. It sits next to VOICE.md (how Onhundred writes) and the protocol (section 3.1 defines a loop).

Last updated: Oct 12, 2026.

## Why this matters

A loop's name is what everyone else sees. It appears on the grid, in every experiment title and in every post about it. A loop nobody understands produces an experiment nobody follows. A loop the agent can't finish produces an experiment that can't succeed.

So the list of 100 is not a to-do list. It is the cast of the whole method.

## What a loop is

A **loop** is one thing you do again and again that ends in a result outside your head: something booked, sent, paid, bought, filed or published. It keeps coming back until someone closes it. The goal of every experiment is for an agent to close it for you.

## The six tests

A proposed loop has to pass all six. If it fails one, rewrite it, split it or drop it.

### 1. The stranger test

**Rule:** someone who has never met you understands the loop from its name alone.
**Why:** loops are published. Internal tools, team names and company jargon mean nothing to the people reading them.
- Fails: "Review the content agents' proposals." (What agents? What proposals?)
- Passes: "Publish the company blog's articles."

### 2. The done test

**Rule:** the loop ends in a result that exists outside your head, and an agent can produce that result: a booking, a sent message, a payment, a purchase, a filed document, a published page.
**Why:** if the result is your own readiness, knowledge or mood, the agent can only ever help. The loop can never be handed over, so its experiment has nowhere to go.
- Fails: "Prepare for tomorrow's meetings." (The result is you being prepared. Only you can be prepared.)
- Fails: "Decide which articles get published." (A decision is a step. The result is the published article.)
- Passes: "Send the agenda before each meeting." / "Send the notes and next steps after each meeting." / "Publish the company blog's articles."

### 3. The action test

**Rule:** at its highest level, the agent does something in the world. It doesn't just remind, track, notify or summarize.
**Why:** a reminder is not a loop. It is a loop you're still doing, with a notification.
- Fails: "Remember what matters to my partner."
- Passes: "Plan and book our date night." / "Buy the birthday and anniversary gifts."

### 4. The one-rule test

**Rule:** one set of success tests fits every time the loop happens. If different occurrences need different rules, the loop is several loops. Split it.
**Why:** an experiment needs one clear bet. A loop that covers three kinds of situations can't be judged by one test, and it takes three times the work to hand over.
- Fails: "Follow up after sales conversations." (A demo, a proposal and an unsigned contract each follow different rules.)
- Passes: "Follow up after a product demo." / "Send the proposal after a discovery call." / "Chase a contract that hasn't been signed."
- The opposite also fails. A single step of a bigger loop ("Find a restaurant") isn't a loop. Merge it into the loop it belongs to ("Plan and book our date night").

### 5. The everyone-has-one test

**Rule:** most readers do a version of this loop too. For work loops, anyone in the same role recognizes it.
**Why:** people follow experiments about their own lives. "Plan the family weekend" needs no explanation, and everyone has an opinion about whether an agent can do it.
- This test ranks loops rather than rejecting them. Some of your 100 will be specific to you. The ones you pick to start with should pass it.

### 6. The ceiling test

**Rule:** the level where the agent does the real thing fits within the area's ceiling (protocol section 7).
**Why:** a loop that has to be booked, sent or paid needs at least "do it, I approve". If its area caps at "help me", the experiment stops before the interesting part.
- Children (R-KID) cap at "help me". "Plan the family weekend" books things, so it belongs in Family (R-FAM), not Children.
- If the ceiling really applies, keep the loop in your 100, but don't pick it to start.

## How to write the name

- **A verb and an object, plus when it happens if that adds clarity.** "Pay the monthly bills." "Send the notes after each meeting."
- **Plain words a stranger would use.** No product names, internal tools or team names.
- **8 words or fewer.**
- **No names of people and no identifying details** (protocol section 10). "My partner," never her name.
- **Start with a verb that ends in a result.**
- **Name the output, not the decision behind it.** A decision is a step inside the loop. Ask "what ships because of this decision?" and name that. The success tests then measure the output.

**Verbs that pass:** book, buy, order, pay, send, reply, schedule, file, submit, renew, cancel, publish, plan and book, collect and send.

**Verbs that usually fail:** decide, choose, remember, remind, track, monitor, keep an eye on, stay on top of, think about, prepare, review, manage, handle. Ask "and then what happens?" and write that instead.

## How to write the scope

The name says what. Done when says when it is finished. **Scope** draws the boundary: what counts as this loop and what doesn't. It is optional and public. 1 to 3 sentences, 60 words or fewer per language.

**Before you leave it empty, ask:** would a stranger or another agent confuse this loop with a neighbor in the same area? If yes, write a scope. If the name and done when already pass the stranger and one-rule tests alone, leave it out.

When you write one, cover only what matters:

1. **What counts** — the recurring cases this loop covers.
2. **What doesn't** — name the neighboring loop or the work that stays with the person.
3. **Fixed constraints** — budget band, channel, roles (never names), or cadence notes that `howOften` can't hold.

**Never:** restate done when, list steps (those belong in experiment stages), or put evidence or history here.

| Loop | Scope |
| --- | --- |
| Plan and book our date night | Covers our regular night out and anniversary plans. Birthday gifts and kid weekends are other loops. Both of us have to be free; no booking that needs a last-minute sitter. |
| Pay the monthly bills | *(none — name and done when already draw the line)* |

## Picking the loops to start with

The inventory needs all 100. The first 3 need to be good stories. On top of the six tests:

- **Fill the slots:** one easy, one hard, one fun (protocol section 6).
  - **Easy:** passes every test with room to spare. It happens often, the rules are clear and the data is digital.
  - **Hard:** passes every test, but the rules are fuzzy or a mistake costs something. It still has to be one loop, not a family of them.
  - **Fun:** passes every test, and you actually want to see an agent try it.
- **Prefer loops the agent can finish.** Pick loops where, at the goal level, the agent completes the result end to end.
- **Prefer loops with a question people care about.** "Can an agent plan a Saturday my kids will remember?" beats "Can an agent sort my receipts?"
- **Keep at least one start loop outside work.** Life and relationship loops are what people share. Work loops are what companies pay for.

## Worked examples

| Proposed | Failed | Rewritten |
| --- | --- | --- |
| Review the content agents' proposals | Stranger | Publish the company blog's articles |
| Decide which articles get published on the company blog | Done | Publish the company blog's articles |
| Decide what's for dinner | Done | Get tonight's dinner on the table |
| Prepare for tomorrow's meetings | Done | Send the agenda before each meeting |
| Follow up after sales conversations | One-rule | Follow up after a product demo (one of three loops) |
| Plan the weekend with the kids | Ceiling (area) | Plan the family weekend, in R-FAM |
| Remember what matters to my partner | Action | Plan and book our date night |

## What an agent returns

One row per loop, with these columns:

| Column | What goes in it |
| --- | --- |
| Code | BRANCH-AREA-NN |
| Loop | The name, following the rules above |
| Done when | The result outside your head, in one line ("The plan is booked and on the family calendar.") |
| Scope | Optional. What counts and what doesn't, when a neighbor could confuse the boundary. Leave empty when name and done when are enough. |
| Branch, Area | Where it lives |
| How often, Hours/week | Estimates, labeled as estimates |
| Time, Frequency, Clear rules, Digital data, Error risk | Scores from 1 to 5 (protocol section 5.2) |
| Evidence | Where in the history the loop showed up |

**Before returning the list, the agent checks every row against the six tests** and rewrites any loop that fails. If a loop can't pass the done test or the action test, it doesn't go in the list.

## Checklist

- [ ] A stranger understands it from the name.
- [ ] It ends in a result outside your head, not a decision.
- [ ] At its highest level, the agent acts. It doesn't just remind.
- [ ] One set of success tests fits every occurrence.
- [ ] Most readers do a version of it (needed for loops you start with).
- [ ] The level where the agent acts fits the area's ceiling.
- [ ] A verb and an object, 8 words or fewer, no names.
- [ ] If two loops in the same area could steal each other's occurrences, each has a scope that draws the line.
- [ ] The scope never restates done when, and never lists steps.
